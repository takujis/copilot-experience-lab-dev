# 経営層向け Copilot デモ環境の構築｜SETUP-02

| 項目 | 内容 |
|---|---|
| **目的** | 顧客に合わせたライブ デモ環境を、デモ用 M365 テナント上に構築する |
| **所要** | 約 90〜120 分（※ 文字起こしの反映に時間がかかるため、デモ前日までの着手を推奨） |
| **利用** | Copilot Chat / Outlook / Teams / SharePoint / OneDrive / Word / Excel |
| **入力** | デモ用 M365 テナント（Microsoft 365 Copilot ライセンス付き）、デモ用アカウント 2〜3 名分、`Copilot_Demo_Outline.docx` |
| **成果** | 顧客に合わせたデモ台本とデモ素材、テナントへのメール・会議・ファイル・文字起こしの配置 |

---

## シナリオ

経営層は、**自社に関係のある話かどうか**を厳しく見ています。
録画済みのデモや、Zava・Contoso といった Microsoft のサンプル企業を使ったデモでは、説得力に欠けて響きません。Microsoft 365 Copilot を紹介するときは、**顧客企業の経営課題に沿ったライブ デモ**を行うことが原則です。

とはいえ、顧客ごとにデモを一から組み立てるのは大変です。本手順では、デモの流れをまとめた **アウトライン文書** をもとに、**Copilot 自身にデモ台本とデモ素材を作らせて**、短時間で顧客専用のデモ環境を構築します。

---

## 事前準備

構築を始める前に、次を揃えます。

| 準備するもの | 内容 |
|---|---|
| デモ用 M365 テナント | Microsoft 365 Copilot ライセンスが割り当てられていること |
| デモ用アカウント | 自分（実演者）に加えて、メール送信役・会議参加役として 2〜3 名分 |
| アウトライン文書 | `Copilot_Demo_Outline.docx`（デモの流れ＋読み上げ台本のサンプル） |
| 顧客情報 | 企業名、業種、経営層の氏名・役割、公表されている重点施策 |

### アウトライン文書について

この文書は、次の 2 部で構成します。

| 構成 | 内容 | Copilot にとっての役割 |
|---|---|---|
| 第 1 部：デモの流れ | 後述「デモ本番の流れ」の 9 ステップを箇条書きにしたもの | 台本の**構成**を決める |
| 第 2 部：台本のサンプル | いずれかの業界向けに書かれた、読み上げ用台本の実例 | 台本の**文体**を決める |

**この文書は、下記からダウンロードできます。**

1. [Copilot デモ アウトライン文書](https://github.com/miookawa/copilot-experience-lab/releases/download/copilot-demo-outline-ja-v1.0.0/Copilot_Demo_Outline.docx)
2. ダウンロードしたファイルを一度開き、正常に利用できることを確認する

配布版の第 2 部は、産業機械メーカーの執行役員を想定した台本です。**そのまま使えます**が、顧客の業界に近い題材へ書き換えると、生成される台本の精度がさらに上がります。

> **書き換える場合**：第 1 部（デモの流れ）は変更しないでください。ここが構成を決めています。書き換えるのは第 2 部だけです。

> **ファイル名について**：本マニュアルでは `Copilot_Demo_Outline.docx` という名前で統一します。
> 別の名前のファイルを使う場合は、後述のプロンプト内の参照もあわせて変更してください。

> **サンプルの言語について**：Copilot はサンプルの文体をまねます。**日本語でデモを行う場合、第 2 部は日本語で用意してください。**
> 英語のサンプルを直訳するのではなく、日本の経営層が自分の言葉で語っている台本として書き下ろすと、読み上げたときの自然さが大きく変わります。

### 生成されるファイル

手順 2 で、次のファイルが自動生成されます。ファイル名は英語のまま扱います。

| ファイル名 | 内容 | 使う場面 |
|---|---|---|
| `Analysis_Data.xlsx` | 分析用のデータ | Analyst のデモ |
| `Meeting_Objectives.docx` | 会議の目的、達成基準、決めたいこと | 会議の事前準備 |
| `Project_Status.docx` | 進捗、マイルストーン、リスク、担当者 | 会議の事前準備 |
| `Risks_and_Dependencies.docx` | 主要リスクと対策、依存関係、未解決の論点 | 会議の事前準備 |
| `Meeting_Script_ReadAloud.txt` | 過去の会議で読み上げる台本 | 文字起こしの作成 |
| `Email_01.txt`〜`Email_04.txt` | 受信トレイに配置するメール本文（4 通） | デモの導入部 |

> **注意**：デモ素材はすべて架空のデータとして生成します。実在の顧客データや個人情報は使用しないでください。

## TRY — 手順

### 1. デモ台本を生成する

1. `Copilot_Demo_Outline.docx` を用意する（事前準備を参照）
2. Copilot Chat にこのファイルを添付し、下記のプロンプトを実行する
3. プロンプト内の `{顧客企業名}`（**4 か所**）を、すべて顧客企業名に置き換える

> **ヒント**：顧客企業・経営層・重点施策に関する情報を、プロンプトの **■ 状況** に書き足すほど、デモのストーリーの質が上がります。実行する前に、後述の「参加者に応じた追記例」もあわせて検討してください。

```text
■ 役割
あなたは、経営層への提案を専門とするコンサルタントです。

■ 状況
{顧客企業名} の経営会議メンバーに対して、Microsoft 365 Copilot の
ライブ デモを行います。添付文書には次の 2 つが含まれています。

・第 1 部：デモの流れをまとめたアウトライン
・第 2 部：別業界向けに作成した読み上げ台本のサンプル

■ 依頼
{顧客企業名} の経営層向けに、そのまま声に出して読める
デモ台本を作成してください。
第 1 部のアウトラインの順序と項目に、厳密に従ってください。

■ 台本を書く前に考えること
執筆に入る前に、次の 4 点を必ず検討し、
その結果を台本に反映してください。

1. {顧客企業名} は、何によって収益を上げているか
2. 経営層は、時間・費用・投資をどこに配分しているか
3. その配分を左右する意思決定は何か
4. その意思決定は、売上・コスト・リスク・スピードの
   どれに効くか

デモで Copilot を使うすべての場面を、
上記のいずれかに必ず結びつけてください。

■ 守ること
・アウトラインの項目を増やさない、減らさない、順序を変えない
・扱う題材は、その業界の実務として自然なものにする
　（受信したメール、会議、調査、データ分析、業界ニュース、会議準備）
・語り口は、落ち着いていて、現実的で、成果に焦点を当てたもの
・実演しながら話している前提の文章にする

■ 避けること
・宣伝的な表現、誇張、機能の羅列
・第 2 部のサンプルに出てくる企業名・業界への言及
・「効率化できます」で終わる説明
　（どの意思決定が、どう速くなるのかまで書く）

■ 出力
・Markdown 形式
・話し言葉の台本。短い段落で、声に出して読める長さに区切る
・操作するタイミングは、簡単なト書きとして角括弧で補う
・台本の中で実際に打ち込むプロンプトは、
　コードブロックにせず、プレーン テキストで示す

■ 言語
・台本本文はすべて自然な日本語で書く
・製品名・機能名は英語表記のまま使う
　（Microsoft 365 Copilot / Researcher / Analyst /
　　Agent Store / WorkIQ など）
・添付文書の中で指定されているファイル名は変更しない

■ 完成の基準
{顧客企業名} の経営層が読んだときに、
「自社のために用意されたデモだ」と感じられること。
```

#### 参加者に応じた追記例

参加する経営層の顔ぶれに応じて、上記プロンプトの末尾に次を追記します。

```text
【追記例 1：取締役会・CFO が中心の場合】
Copilot の価値を、次の観点から語ってください。
・業績見通しの精度が上がること
・人を増やさずに処理量を増やせること
・分析結果が出るまでの待ち時間が短くなること
・情報が揃わないまま判断する場面が減ること

【追記例 2：規制の厳しい業界（金融・製薬・エネルギーなど）の場合】
次の点を、台本の中で明確に触れてください。
・データがどこに保存され、どの範囲に留まるか
・入力した内容がモデルの学習に使われないこと
・出力の根拠をたどれること、記録が残ること
・従業員が個人的に外部の AI を使う状態と比べて安全であること

【追記例 3：DX 推進部門が中心の場合】
Copilot を次のように位置づけてください。
・エージェントを載せていくための土台
・業務プロセスを段階的に変えていく出発点
・既存システムの置き換えではなく、その上に重ねるもの
```

### 2. デモ素材を生成する

台本ができたら、その台本に沿った**デモ素材一式**を Copilot に作らせます。ここでも `{顧客企業名}`（**2 か所**）を置き換えてから実行します。

```text
■ 依頼
{顧客企業名} 向けのデモを最初から最後まで成立させるために
必要なファイルを、すべて作成してください。
完成したら、フォルダー分けした 1 つの .zip にまとめてください。

────────────────────────────────
作成物 1：分析用の Excel ブック（Analyst のデモで使用）
────────────────────────────────
・ファイル名：Analysis_Data.xlsx
・データ行数は 150〜300 行
・列は次のとおり（列名は英語のまま作成すること）
　Date … 日付
　Region … 地域
　BusinessUnit … 事業部門
　CustomerSegment … 顧客セグメント
　ProductService … 製品・サービス名
　Channel … 販売・接点チャネル
　Metric1 … 数量、売上、リードタイムなどの主要指標
　Metric2 … コスト、不具合件数、解約率などの副指標
　FeedbackText … 顧客の自由記述コメント
　CaseType … 案件の種類
　Priority … 優先度

・FeedbackText は自然な日本語で書くこと
・このデータに対して、次の分析が成立すること
　- コメントを 5 段階で感情スコア化できる
　- 肯定／否定のラベルを付けられる
　- 否定的なコメントを 3〜5 個のテーマに分類できる
・{顧客企業名} の業界として現実的な数値にすること
・分析すると、意味のある発見が 2〜3 個は自然に出てくるよう
　数値とコメントを設計すること

────────────────────────────────
作成物 2：会議準備で参照させる文書（3 点）
────────────────────────────────
Copilot が会議準備の際に読みに行く資料として、
次の 3 点を作成してください。

・Meeting_Objectives.docx
　… A4 で 1〜2 ページ。この取り組みの目的、達成基準、
　　　会議で決めたいことを記載

・Project_Status.docx
　… 進捗の状態（青・黄・赤の 3 段階）、マイルストーン、
　　　顕在化しているリスク、各担当者、今後 30 日の予定

・Risks_and_Dependencies.docx
　… 主要なリスクとその対策、他部門・他システムへの依存、
　　　まだ結論の出ていない論点

条件：
・3 点すべてで、施策名・登場人物・数値・優先順位を一致させること
・AI が書いた説明文ではなく、社内で実際に回覧されている
　資料として読める文章にすること

────────────────────────────────
作成物 3：過去の会議の読み上げ台本
（Teams で録画し、WorkIQ の検索デモに使用）
────────────────────────────────
・ファイル名：Meeting_Script_ReadAloud.txt
・1 人が音読して 5〜8 分になる分量
・内容には次を含めること
　- その会議で決まったこと
　- 検討の際のトレードオフ（見送った案とその理由）
　- 本題から少し外れた雑談

・さらに、後から検索して見つけ出す「探しもの」を
　1 つだけ仕込んでください。
　例：誰かが薦めたドキュメンタリー、書籍、取引先の名前など

【探しものの仕込み方 — ここが最も重要】

デモでは、記憶があいまいなまま検索します。
そのため、会議台本の言葉と検索するときの言葉が
「意味は同じだが、単語は違う」状態である必要があります。

守ること：
(1) 探す対象の種類は一致させる
　　検索する側が「ドキュメンタリー」を探すなら、
　　台本側も必ず映像作品に触れること。
　　報告書や調査結果などに置き換えないこと。

(2) 話題の分野は一致させる
　　検索する側が物流・配送の話なら、
　　台本側も同じ分野を別の言い方で語ること。
　　消費者動向など、隣の話題にずらさないこと。

(3) 単語は変える。意味は重ねる
　　検索するときに使う単語を、台本にそのまま出さないこと。
　　言い換えは、漢字・カタカナ・ひらがなの表記違いでは不十分。
　　語そのものを別の語に変えること。
　　例：「配送遅延」と「荷物がなかなか着かない状況」

(4) 触れ方は、あくまで雑談として
　　議題としてではなく、話の合間にふと出た一言として
　　登場させること。引用や資料紹介のように書かないこと。

(5) 合格の条件
　　「前に誰かが話していた気がするのですが、
　　　名前が思い出せなくて」といったあいまいな聞き方で、
　　その一言にたどり着けること。

────────────────────────────────
作成物 4：メールの下書き（4 通）
────────────────────────────────
Outlook にそのまま貼り付けられる短いメールを、
.txt ファイルで 4 通作成してください。
ファイル名は Email_01.txt 〜 Email_04.txt とします。

・Email_01：上司から届いた、至急の相談メール
　（Researcher を使いたくなる内容にすること）
・Email_02：作成物 1 の Excel ブックを送ってきた、同僚からのメール
・Email_03：作成物 2 の文書を参照するよう促す、会議に関するメール
・Email_04：対応が必要な私用の連絡
　（社内申請の締切など、業務の合間に片付ける必要がある短い用件。
　　機微な内容にはしないこと）

────────────────────────────────
全体のルール
────────────────────────────────
・登場する企業・人物・数値はすべて架空とすること
　実在の顧客データや個人情報は一切使用しないこと
・4 つの作成物すべてで、登場人物・施策名・数値を一致させること
・メール 4 通は、それぞれ差出人の立場（上司・同僚など）が
　文面から自然に伝わるようにすること
・文書・メール・会議台本の本文は、すべて自然な日本語で書くこと
・指定したファイル名と Excel の列名は、英語のまま変更しないこと
・製品名・機能名は英語表記のまま使うこと
　（Researcher / Analyst / WorkIQ など）

────────────────────────────────
出力
────────────────────────────────
・ダウンロードできる 1 つの .zip にまとめること
・この環境で .zip を作れない場合は、
　指定どおりのファイル名とフォルダー構成のまま
　全ファイルの中身を出力すること
　（こちらで手作業でファイルにします）
```

### 3. デモ用テナントに素材を配置する

生成された .zip をダウンロードし、中身を**手作業でデモ用 M365 テナントに入れていきます**。
一部の操作は、**自分以外のデモ用アカウント**で行ってください（受信トレイに「他の人から届いたメール」として見せるためです）。

1. `Analysis_Data.xlsx` を添付したメール（`Email_02`）を、同僚役のアカウントから自分宛てに送信する
2. Researcher を使いたくなる**至急のメール**（`Email_01`）を、上司役のアカウントから自分宛てに送信する
3. 会議に関するメール（`Email_03`）を、同僚役のアカウントから自分宛てに送信する
4. 私用の連絡（`Email_04`）を、自分宛てに送信する
5. 会議準備用の文書（`Meeting_Objectives.docx` / `Project_Status.docx` / `Risks_and_Dependencies.docx`）を SharePoint サイトにアップロードする

### 4. ステークホルダー定例会議を作成する

デモで使うステークホルダー定例会議を、Copilot に作らせます。
これは、施策の意思決定に関わる主要な関係者が集まる週次会議、という位置づけです。
**デモ本番と同じ曜日**で、**過去 2 週間・今後 2 週間**の週次会議として作成します。`{ }` の中を置き換えて実行してください。

```text
デモで使うステークホルダー定例会議を、私の予定表に登録してください。
この会議は、施策の意思決定に関わる主要な関係者が集まる週次会議です。

・毎週 {__曜日__} の {__時刻__} 開催
・過去 2 週間分と、今後 2 週間分を作成すること
・出席者に {__デモ用アカウント2__} と {__デモ用アカウント3__} を追加すること
・会議の本文には、先ほど作成した資料の内容をもとにした
　詳しい議題を記載すること
```

### 5. 過去の会議に文字起こしを作る

WorkIQ のセマンティック検索デモ（過去の会議で何気なく出た一言を、後から探し出す）を成立させるために、**過去の会議録**を作ります。

1. 前週分のステークホルダー定例会議に参加する
2. Teams で**文字起こしを開始**する
3. 手順 2 で生成した `Meeting_Script_ReadAloud.txt` の台本を、自然に読み上げる
4. 会議を終了し、文字起こしが保存されたことを確認する

> 文字起こしと会議の要約が Copilot から参照できるようになるまで、多少時間がかかる場合があります。**デモ前日までに**済ませておくことをおすすめします。

## デモ本番の流れ

構築した環境は、次の流れでデモできる状態になっています。デモ前の動作確認にも使えます。
この 9 ステップが、`Copilot_Demo_Outline.docx` の第 1 部に記載すべき内容です。

| # | 場面 | 確認するポイント |
|---|---|---|
| 1 | 「今日一日の予定を整理して」と依頼する | 対応が必要な私用の連絡（社内申請の締切など）、Researcher を使いたくなる社内メール、Excel が添付されたメール、当日の予定（ステークホルダー定例会議を含む）が返ること |
| 2 | 至急のメールをもとに Researcher を実行する | Agent Store から Researcher を呼び出し、バックグラウンドで処理が進むこと |
| 3 | メールの Excel を開いて Analyst を実行する | ブックに対する深い分析と、Python コードによる高度な分析が動くこと |
| 4 | 業界ニュースの日次まとめを作成する | プロンプトのスケジュール実行を提示できること |
| 5 | 会議の事前準備を依頼する | `/`（スラッシュ）で参照先（人・ファイル・会議・メール）を指定できること |
| 6 | 過去の会議で出た一言を探す | WorkIQ のセマンティック検索で「探しもの」を見つけ出せること |
| 7 | 各アプリの Copilot をひと巡りする | Outlook / PowerPoint / Word を回り、アプリを行き来せずに作業できること |
| 8 | Researcher の結果を確認する | 多段階の推論の過程と詳しい結果を提示し、Word に書き出せること |
| 9 | Word でポッドキャストを生成する | 生成されたポッドキャストを再生できること |
